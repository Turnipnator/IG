# Fully-pinned dependency set — the ONLY thing the Docker image installs.
#
# WHY THIS EXISTS
# ---------------
# requirements.txt uses >= ranges and the deploy path rebuilds with
# `docker compose build --no-cache`, so every rebuild re-resolved every
# package to whatever was newest on PyPI that day. That is not theoretical:
# by 2026-08-21 production had silently crossed FOUR major versions against
# the ranges in requirements.txt — pandas 2->3, lightstreamer 1->2,
# python-telegram-bot 20->22, yfinance 0->1.
#
# That matters more here than in most projects. The edge is .ewm() /
# .resample() / .rolling() / .shift() arithmetic, so a pandas minor bump
# changes signal numbers with no exception, no log line, and no crash — it
# presents exactly like the htf_series look-ahead bug did: backtest and live
# disagree and the strategy gets blamed.
#
# HOW IT WAS BUILT
# ----------------
# Captured from `pip freeze` inside the RUNNING ig-trading-bot container on
# 2026-08-21 (up 26h, healthy, Python 3.12.14). It pins the known-good
# production state as it actually ran — deliberately NOT today's PyPI latest
# and NOT either local venv (venv has pandas 2.3.3, .venv-bt has 3.0.3, both
# on Python 3.14). This file is a freeze, not an upgrade.
#
# HOW TO CHANGE IT
# ----------------
# Never hand-edit a version to "just try" a bump. Either let Dependabot open
# the PR (CI must pass before rebuild-watcher.sh will deploy it), or bump
# requirements.txt and re-freeze from a container built off that change.
#
# requirements.txt remains the human-edited statement of intent — direct
# dependencies and why. This file is the machine-resolved consequence.
